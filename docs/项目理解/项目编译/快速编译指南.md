# 快速编译指南

## 问题
修改代码后，运行 `npm run compile` 会编译整个项目，耗时很长。

## 解决方案：使用 Watch 模式（推荐）

### 方法 1：使用 watch-client（只编译客户端代码，最快）

在**第一个终端**运行（保持运行）：
```bash
npm run watch-client
```

这样：
- ✅ 只编译客户端代码（包括你修改的 `actionWidget.ts`）
- ✅ 自动监听文件变化
- ✅ 修改后自动重新编译
- ✅ 比完整编译快很多

### 方法 2：使用完整 watch（包含扩展）

如果需要同时编译扩展：
```bash
npm run watch
```

### 使用步骤

1. **启动 watch 模式**（在后台运行）：
   ```bash
   npm run watch-client
   ```

2. **修改代码**（如 `actionWidget.ts` 或 `actionWidget.css`）

3. **保存文件** → watch 模式会自动检测并重新编译

4. **刷新浏览器** → 看到最新效果

### 停止 watch 模式

按 `Ctrl+C` 停止 watch 模式。

## 对于 CSS 文件的特殊说明

如果你只修改了 CSS 文件（如 `actionWidget.css`）：
- **可能不需要重新编译 TypeScript**
- 直接**刷新浏览器**即可看到效果
- 如果不行，再运行 watch 模式

## 快速测试流程

```bash
# 终端 1：启动 watch（保持运行）
npm run watch-client

# 终端 2：启动服务器
./scripts/code-server.sh --without-connection-token --port 3000

# 然后：
# 1. 修改代码
# 2. 保存文件
# 3. 等待 watch 自动编译（通常几秒钟）
# 4. 刷新浏览器
```

## 性能对比

- `npm run compile`: 编译整个项目，需要 5-10 分钟
- `npm run watch-client`: 只编译客户端，首次 2-3 分钟，后续修改只需几秒到几十秒

## 注意事项

1. **首次运行 watch**：需要先编译一次，可能需要 2-3 分钟
2. **后续修改**：只编译修改的文件，通常只需几秒钟
3. **内存占用**：watch 模式会占用一些内存，但比完整编译少
4. **停止 watch**：修改完成后可以按 `Ctrl+C` 停止
